# Portfolio Expert Checklist (Full-Stack)

Use this checklist to verify portfolio readiness for both freelance clients and full-time big-tech style roles.

Status legend:
- [ ] Missing
- [~] In Progress
- [x] Done

## 1) Core Projects (3 Required)

### Project A: B2B SaaS Dashboard
- [ ] Multi-tenant data model
- [ ] Auth + RBAC (at least Admin/Manager/User)
- [ ] Billing/subscription flow
- [ ] Audit log for critical actions
- [ ] Reporting + export (CSV/PDF)
- [ ] Live demo URL
- [ ] Public/private repo with clear README

### Project B: E-commerce / Transaction System
- [ ] Product/cart/checkout flow
- [ ] Payment integration (Stripe/Omise/PayPal at least one)
- [ ] Webhook verification + idempotency handling
- [ ] Order lifecycle states (created/paid/fulfilled/cancelled/refunded)
- [ ] Refund flow (full or partial)
- [ ] Inventory consistency checks
- [ ] Live demo URL
- [ ] Repo + README

### Project C: Real-time / Workflow App
- [ ] Real-time updates (WebSocket or SSE)
- [ ] Background jobs/queue
- [ ] Notification pipeline
- [ ] Retry/backoff for failures
- [ ] Failure recovery plan documented
- [ ] Monitoring dashboard or metrics screen
- [ ] Live demo URL
- [ ] Repo + README

### Project D: Cloud / DevOps / MLOps Platform
- [ ] Architecture diagram for cloud landing zone / network boundary
- [ ] Terraform or IaC modules for core infrastructure
- [ ] Containerized service with Docker
- [ ] CI/CD pipeline for build/test/deploy
- [ ] Identity/access model documented (RBAC, secrets, managed identity, etc.)
- [ ] Monitoring/cost guardrail plan documented
- [ ] Mini case study for AI/ML lifecycle or platform workflow
- [ ] Repo + README

## 2) Production Engineering Quality (Per Project)
- [ ] Architecture diagram (high-level)
- [ ] API contract/doc (OpenAPI/Postman/Markdown)
- [ ] Validation + error handling standards
- [ ] Unit tests for core business logic
- [ ] Integration tests for DB/API paths
- [ ] E2E test for critical user journey
- [ ] CI pipeline (lint + test + build)
- [ ] CD/deploy steps documented
- [ ] Secrets management policy (no hardcoded secrets)
- [ ] Basic security controls (authz, rate limit, input sanitization)
- [ ] Performance notes (index/cache/query optimization)
- [ ] Decision log with trade-offs
- [ ] Demo note or screenshot flow for reviewer

## 3) Portfolio Website Quality
- [ ] Project cards with role/scope/impact
- [ ] Case study format: Problem -> Decision -> Trade-off -> Result
- [ ] Stack rationale section (why this tech)
- [ ] Metrics section (latency, error rate, lighthouse, uptime, etc.)
- [ ] Demo + repo + docs links visible
- [ ] Mobile-friendly and clean information architecture
- [ ] Contact + hiring CTA

## 4) Evidence of Senior/Expert Thinking
- [ ] At least 1 incident postmortem write-up
- [ ] At least 1 migration note (legacy -> modern)
- [ ] At least 1 system design document per major project
- [ ] Clear trade-off explanations in docs
- [ ] Backlog/milestone tracking evidence
- [ ] Meaningful commit/PR history
- [ ] At least 1 cloud cost/performance trade-off write-up
- [ ] At least 1 security/governance review note

## 5) Interview/Freelance Readiness
- [ ] 3 mock interviews completed (coding/system/behavioral)
- [ ] DSA medium problems solved consistently under time limit
- [ ] Can explain architecture in 5-10 minutes clearly
- [ ] Proposal template ready (scope/timeline/risk/pricing)
- [ ] Pricing packages ready (basic/pro/premium)
- [ ] Delivery checklist ready (kickoff -> handoff)

## 6) Acceptance Criteria (Solid 100)
You can call your portfolio "solid expert-level" when all are true:
- [ ] 3 core projects are fully complete and publicly demonstrable
- [ ] Every project has tests + deploy + docs + architecture note
- [ ] Portfolio website communicates outcomes, not just features
- [ ] You can defend technical decisions and trade-offs confidently
- [ ] A reviewer can run your project from README in <= 15 minutes
